0. 给 AI 执行者（Agent）的说明

本文档是给 AI 编程 Agent（如 Claude Code、Cursor、豆包、OpenClaw 等）和开发工程师共同使用的手册。执行规则如下：

  • 按 Step 顺序执行：每章末尾有「✅ 验收标准」，只有全部通过才进入下一步；失败时先读错误信息，修复后重跑该步。
  • 命令环境：本机为 Windows + PowerShell。文档中的命令均给出 PowerShell 写法；PowerShell 禁止用 && 串联命令，多步操作请拆行执行。
  • 路径注意：MoneyPrinterTurbo 官方要求项目路径不含中文/空格/特殊字符（如 C:\Users\24688\Desktop\自动化剪辑 含中文，建议其代码克隆到 C:\dev\ 下）。
  • API Key：文档中出现的 YOUR_... 均为占位符，需由用户提供后替换。
  • 可自动化：本系统完成后暴露两层自动化入口——① 编排网关 REST API（Step 6）供任何程序调用；② MCP Server（Step 7）供 AI Agent 直接以工具方式调用。
  • 合规红线：采集功能仅用于学习/自用数据研究；DTK 与 XHS 均有限制条款，商用需另行评估（见 §15）。
  • 并行 / 串行：开发阶段与运行时哪些任务可派子智能体并行、哪些必须串行，见「Step 6.5 任务并行与串行编排策略」；并行时必须遵守并发上限、统一输出契约和失败隔离。
💡 给 Agent 的速读路径：先读 §1–§4 理解架构 → 按 §5–§13 的 Step 逐步实现 → 每步执行「验收标准」→ 完成后跑 §14 端到端验收。附录 A/B/C 是接口与提示词参考，实现对应模块时查阅。

1. 项目概述与目标

1.1 项目是什么

构建一个对标「一木AI产品」的自媒体智能体工作台：用户粘贴一条视频/博主链接或关键词，系统自动完成数据采集 → AI 拆解分析 → 文案生成 → 素材沉淀（飞书表格）的完整闭环，并支持一键生成短视频。

1.2 核心能力清单（对标一木 6 大智能体）

#能力实现方式数据来源/引擎
1爆款视频拆解链接 → DTK 采集 → LLM 拆解DTK + AI 引擎
2博主对标拆解博主主页 → 批量采集作品 → LLM 归纳打法DTK + AI 引擎
3账号复盘诊断导入自己账号数据 → LLM 反推卡点+建议CSV/飞书导入 + AI 引擎
4关键词找爆款关键词 → 搜索采集 → 拆流量结构 → 复刻建议DTK 搜索 + AI 引擎
5原创爆款文案生成选题/开头类型 → 生成文案AI 引擎（复用 MPT LLM 链路）
6仿写三件套仿结构 / 提炼改写 / 去重AI 引擎
7一键成片文案 → 配音/素材/字幕/合成MoneyPrinterTurbo
8素材库沉淀采集+拆解结果入库、飞书同步PostgreSQL/SQLite + 飞书 API

1.3 成功标准（MVP）

  1. 粘贴任意抖音/TikTok 链接 → 返回结构化拆解报告（钩子、结构、节奏、数据、复刻建议）。
  2. 输入博主主页链接 → 返回对标分析报告。
  3. 输入关键词 → 返回爆款视频列表 + 流量结构分析。
  4. 输入选题 → 生成爆款风格文案 → 可选一键生成短视频。
  5. 所有结果可查询历史并同步到飞书多维表格。
  6. AI Agent 可通过 MCP 工具直接完成以上全部操作。

2.1 为什么这样融合（技术可行性）

  • 统一语言：DTK、MPT、自建模块全部为 Python + FastAPI，可共享依赖与调用范式。
  • HTTP 解耦：各组件独立进程/容器，通过 REST API 通信，任一组件的平台接口失效不影响整体。
  • 自动化入口现成：DTK v5 自带 MCP（/mcp），MPT 自带 REST API + 官方 AI Skill；自建层只需做「编排 + 业务提示词」。
  • 成本可控：LLM 用 DeepSeek 等 OpenAI 兼容 API（约 ¥1–2/百万 token）；TTS 用 MPT 内置 Edge TTS（免费）；素材用 Pexels/Pixabay（免费）。

def collect(url: str) -> dict:

9.2 LLM 客户端（Key 运行时注入；未配置自动降级 Mock）

# llm.py —— 不硬编码、不依赖启动时的环境变量
from typing import Any
import json
from settings_store import get_llm_settings   # 见 §10.4，运行时从配置库读取

MOCK = True   # 开发期开关；可由设置项 app.mock 控制

def chat(system: str, user: str, json_mode: bool = True, model: str | None = None) -> Any:
    s = get_llm_settings()                  # {base_url, api_key, model}
    if MOCK or not s.get("api_key"):
        return mock_result()                # 无 Key：返回样例 JSON，照样跑通链路
    from openai import OpenAI
    client = OpenAI(api_key=s["api_key"], base_url=s["base_url"])
    resp = client.chat.completions.create(
        model=model or s.get("model", "deepseek-chat"),
        messages=[{"role": "system", "content": system},
                  {"role": "user", "content": user}],
        response_format={"type": "json_object"} if json_mode else None,
        temperature=0.6,
    )
    return resp.choices[0].message.content

def mock_result() -> str:
    # 必须符合 §9.3 的 schema，供前端/网关先联调
    return json.dumps(
        {"title": "[示例]标题", "hook": "[示例]钩子分析",
         "structure": [], "replicable_points": []}, ensure_ascii=False)
🔑 Key 全程可后置：① 开发期 MOCK=True 用样例数据；② 也可接本地 Ollama（base_url=http://localhost:11434/v1，key 任意填，免费）；③ 系统上线后在前端「系统设置」页填入真实 Key（走 PUT /api/v1/settings，加密存库，不进代码库）。未配置 Key 时接口返回样例或友好提示，绝不报错中断。

9.4 FastAPI 入口（app.py 摘要）

# app.py
from fastapi import FastAPI
from pydantic import BaseModel
import llm, schemas, prompts

app = FastAPI(title="studio-analytics", docs_url="/docs")

class AnalyzeReq(BaseModel):
    raw: dict          # DTK 采集到的作品/博主数据 JSON
    kind: str          # breakdown | blogger | review | keywords | rewrite

@app.post("/analyze")
def analyze(req: AnalyzeReq):
    system = prompts.load(req.kind)          # 从 prompts/*.md 读取
    content = prompts.render(req.kind, req.raw)
    out = llm.chat(system, content)
    return {"ok": True, "kind": req.kind, "result": out}

@app.get("/health")
def health(): return {"status": "ok"}

10.4 鉴权与凭据运行时管理

网关对所有 /api/v1/* 校验请求头 X-API-Key: 【GATEWAY_API_KEY】。下游凭据（DTK_API_KEY、LLM Key、飞书凭据）不必写死在环境变量：可在「系统设置」页运行时填写，经加密后存于配置库；环境变量仅作为初始默认值。

# settings_store.py —— 凭据运行时读写（加密）
from cryptography.fernet import Fernet
import json, os

_KEY = os.environ.get("SETTINGS_SECRET") or Fernet.generate_key()
f = Fernet(_KEY)
_store = "settings.json.enc"

def save_settings(data: dict):
    blob = f.encrypt(json.dumps(data, ensure_ascii=False).encode())
    open(_store, "wb").write(blob)

def load_settings() -> dict:
    if not os.path.exists(_store): return {}
    return json.loads(f.decrypt(open(_store,"rb").read()))

def get_llm_settings() -> dict:
    return load_settings().get("llm", {})

def public_settings() -> dict:
    # 给前端：只暴露 base_url/model 和"是否已填 Key"，绝不返回明文
    s = load_settings().get("llm", {})
    return {"base_url": s.get("base_url"), "model": s.get("model"),
            "api_key_configured": bool(s.get("api_key"))}

Step 6.5 · 任务并行与串行编排策略（给 AI 子智能体）

本节明确告诉 AI：哪些阶段可以派子智能体并行执行、哪些必须串行。同时适用于「开发实施阶段」和「系统运行时任务」。

0.1 最高判断规则（AI 先读这条）

🔑 唯一判断标准：任务 B 的输入是否依赖任务 A 的输出？
· 依赖（B 需要 A 的结果才能开始）→ 必须串行，禁止提前执行。
· 不依赖（输入相互独立、写不同资源、无顺序要求）→ 可以并行，派子智能体 / 多 worker 同时执行。

0.2 并行执行的 4 条硬约束

  1. 限并发：用 asyncio.Semaphore 控制并发数，遵守平台限流（DTK 演示站 30 次/10 秒；飞书写入约 100 次/分钟；LLM 按账户 RPM）。
  2. 统一契约：并行子任务必须输出统一 JSON Schema（字段见 §9.3），否则无法聚合。
  3. 失败隔离：单个子任务失败 不拖垮整批——try/except 收集错误，标记失败项，最后可单独重试失败项。
  4. 共享资源安全：并行写库 / 用身份池要幂等（主键去重）或加锁，禁止多个子任务写同一条记录。

3.1 通用并行执行器（带并发上限 + 失败隔离）

# studio/gateway/parallel.py
import asyncio

async def map_parallel(items, worker, concurrency: int = 5):
    """对 items 并行执行 worker，返回逐项结果，单项失败不影响整体。"""
    sem = asyncio.Semaphore(concurrency)
    async def _wrap(item):
        async with sem:
            try:
                return {"ok": True, "item": item, "result": await worker(item)}
            except Exception as e:
                return {"ok": False, "item": item, "error": str(e)}
    return await asyncio.gather(*[_wrap(i) for i in items])

3.2 analyze-blogger 的 Map-Reduce 编排

async def run_analyze_blogger(task, payload):
    # ① 串行：分页采集博主作品（有顺序/翻页依赖，不能并行）
    posts = await dtk.author_posts(payload["url"], limit=payload.get("post_limit", 20))
    # ② 并行 Map：逐条拆解（互不依赖，限流 5 并发）
    results = await map_parallel(
        posts,
        lambda p: analytics.analyze({"raw": p, "kind": "breakdown"}),
        concurrency=5)
    ok = [r["result"] for r in results if r["ok"]]
    failed = [r["item"] for r in results if not r["ok"]]
    # ③ 串行 Reduce：归纳博主整体打法
    summary = await analytics.summarize_blogger(ok)
    summary["failed_items"] = failed          # 暴露失败项，供后续重试
    task.complete(summary)
⚠️ 禁止并行的情况（AI 自查）：① 下游有限流且未做信号量；② 任务间共享同一可变记录；③ 后一步需要前一步聚合结果；④ MPT 单条视频内部各环节（其自身已串行编排，不要外部重复并行触发同一任务）。
✅ 验收标准：① 能说清每个业务任务的串/并行阶段；② 用 map_parallel 跑 analyze-blogger，N 条作品并发拆解、最终聚合成功；③ 故意让 1 个子任务失败，整批仍完成且 failed_items 正确记录；④ 并发数不超过设定上限（可日志验证）。

  3. 【可选】飞书凭据：在「系统设置」填 app_id/app_secret，并在同步请求带 app_token、table_id，即可把报告写入多维表格。

端口说明：MPT 官方默认 8080，本机 8080 被用户其他项目（sanshi）的 Docker 容器占用，故全链路统一改用 8088（网关用环境变量 MPT_URL=http://127.0.0.1:8088）。

E.6.1 MPT 客户端（提交 → 轮询 → 取片）

# studio/gateway/clients/mpt.py
import httpx

class MPTClient:
    def __init__(self, base_url: str, api_key: str = ""):
        self.base = base_url.rstrip("/")
        # Token 请求头以 app/controllers/base.py 的 verify_token 为准
        self.headers = {"Authorization": f"Bearer {api_key}"} if api_key else {}

    async def create_video(self, params: dict) -> str:
        async with httpx.AsyncClient(timeout=30) as c:
            r = await c.post(f"{self.base}/api/v1/videos", json=params, headers=self.headers)
            r.raise_for_status()
            return r.json()["data"]["task_id"]

    async def get_task(self, task_id: str) -> dict:
        async with httpx.AsyncClient(timeout=30) as c:
            r = await c.get(f"{self.base}/api/v1/tasks/{task_id}", headers=self.headers)
            r.raise_for_status()
            return r.json()["data"]

    def stream_url(self, path: str) -> str:
        return f"{self.base}/api/v1/stream/{path}"
